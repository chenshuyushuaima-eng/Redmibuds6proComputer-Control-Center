## 结论与范围

Windows 11 可以通过蓝牙直接与当前 REDMI Buds 6 Pro（国行，固件 1.1.9.9）交换控制协议消息。已建立连接并完成双向认证、设备信息读取、运行信息读取以及 12 类配置查询。构建桌面控制应用所需的通信基础已验证。

当前证据只覆盖认证和读取。降噪切换等设置写入、长期连接稳定性、完整手机功能覆盖和固件更新尚未验证。没有运行图形应用，也没有发送任何设置写入指令。

## 通信实现

- Windows 使用 `BluetoothDevice.GetRfcommServicesAsync` 查询服务，通过返回的 `ConnectionHostName` 与 `ConnectionServiceName` 建立 `StreamSocket`。
- 这台设备实机发布的 miwear UUID 是 `0000fd2d-0000-1000-8000-00805f9b34fb`。其他型号参考项目使用的 `df21fe2c-2515-4fdb-8886-f12c4d67927c` 在这台设备上没有出现；不能硬编码通用 RFCOMM 信道 28。
- 帧格式为 `FE DC BA | type | opcode | length(2, big-endian) | [status] | seq | payload | EF`。解析需要处理拆包、粘包、无效长度和返回状态。
- 已实测认证 `0x50 / 0x51`、设备信息 `0x02`、运行信息 `0x09`、读取配置 `0xF3`。
- 图形界面应只在收到成功应答并回读状态后显示新设置；未知配置字段保留，避免将参考型号的选项直接套用到当前固件。

## 文件与证据

- `tools/RfcommProbe.cs`：Windows 原生 RFCOMM、协议分帧、认证与只读查询。
- `tools/BudsAuthentication.cs`：开源认证算法的 C# 移植。
- `tools/WinrtAwaiter.cs`：有超时的 WinRT 操作等待。
- `tools/build-probe.ps1`：诊断程序编译入口。
- 原始实机日志含本地设备地址，不在公开项目中保留；本文保存可公开的通信结论。

早期原生 Winsock 连接实验未成功；最终成功路径是 Windows WinRT RFCOMM 服务发现及连接。清理时删除了这些旧实验输出，保留诊断工具源码及协议记录。
